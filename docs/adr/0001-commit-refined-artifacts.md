# 정제 산출물은 저장소에 커밋한다

수집·파싱·지오코딩·LLM 호출은 개발자 PC에서만 돌고, CI는 사이트만 빌드해 배포한다. 그래서 CI가 읽을 수 있도록 정제 산출물(도시별 레코드 CSV, 지오코딩 캐시, 헤더 매핑 캐시, 비식당 판별 캐시, 폐업 판정 결과)을 `data/` 아래에 커밋한다. 원본과 인허가 원본, `dist/`는 커밋하지 않는다. 파일당 상한은 20MB이고 CI가 검사한다.

## Considered Options

- **외부 저장소(릴리스 자산·오브젝트 스토리지)에 두고 CI가 내려받기**: 두 사람이 9월 20일까지 7개 도시를 붙이는 일정에서 인증·업로드 절차가 한 겹 더 붙고, 산출물의 변경 이력이 코드와 분리된다.
- **Git LFS**: Cloudflare Pages 빌드 환경과 협업자 클론에서 별도 설정이 필요하고, public 무료 저장소의 대역폭 한도를 쓴다.
- **커밋(채택)**: 클론 한 번으로 재현되고, 캐시 덕분에 검색 API 키 없이도 지도를 다시 만들 수 있다. 대가는 히스토리 크기이며, 도시별 분할과 20MB 상한으로 억제한다.

## Consequences

- 캐시는 추가만 하고 지우지 않는다. 지우려면 파일을 직접 삭제한다.
- 도시별로 파일을 갈라 두어야 상한을 지키고 충돌을 피한다. 도시 무관 캐시만 `data/_shared/`에 둔다.
- 인허가 원본은 저장소 밖에 두고, 좌표 보강과 폐업 대조의 결과만 커밋한다.
