# HWP·HWPX 원본 처리 경로 조사

조사일: 2026-09-10. 목적: **HWP·HWPX 원본 처리**의 기본 읽기 경로 결정에 필요한 사실 확인.
사용자는 두 형식 모두 지원 대상으로 확정했다. 이 문서는 조사 근거이며 지원 완료 보고나 정책 전문이 아니다. 최종 결정은 [HWP·HWPX 원본 처리](https://github.com/snowjaewon/OfficialDeliciousMap/issues/19)의 해결 코멘트를 따른다.
원본 다운로드, 패키지 설치, 파서 실행, 변환 성공률 측정은 하지 않았다. 앞선 프로토타입에서 제외된 HWP 3개·HWPX 2개는 성공 근거가 아니다.

## 권장 경로와 비교

다음은 공식 형식 설명과 원저자 자료에서 도출한 **설계 제안**이다.

| 후보 | 확인한 기능·제약 | 제안 |
| --- | --- | --- |
| HWP5: `olefile` + 자체 형식 어댑터 | olefile은 OLE 저장소·스트림 접근만 제공한다. HWP 레코드와 표 해석은 별도로 구현해야 한다. 한컴 명세에 필요한 본문·문단·표·셀 구조가 공개돼 있다. [HWP5 명세](https://cdn.hancom.com/link/docs/한글문서파일형식_5.0_revision1.2.pdf), [olefile](https://github.com/decalage2/olefile) | 기본 후보. 정식 코드에서 명세를 바탕으로 제한된 추출기를 구현하고, 읽기 성공과 표 격자 복원 성공을 구별한다. |
| HWP5: `pyhwp` | HWP5 스트림 분석·추출, 실험적 ODT·텍스트 변환을 제공한다. 표 모델에 행·열 수, 페이지 나눔과 제목 반복 속성이 있다. [README](https://github.com/mete0r/pyhwp), [표 모델](https://github.com/mete0r/pyhwp/blob/master/src/hwp5/binmodel/tagid61_table.py) | 비교 후보로 보류. 현재 Python 호환성·표 보존을 검증하지 않은 상태로 기본 의존성으로 확정하지 않는다. |
| HWPX: ZIP + XML 자체 어댑터 | ZIP 안의 XML 문서이며 `content.hpf`의 manifest와 spine으로 구성 파일·읽기 순서를 찾는다. 본문은 여러 section 파일일 수 있다. [한컴 구조 설명](https://tech.hancom.com/hwpxformat/) | 기본 후보. 모든 구역을 문서 순서로 읽고 문단·표 구조를 유지한다. |
| HWPX: 한컴 `hwpx-owpml-model` | 문서 요소를 추출·저장하는 C++ 모델. README 빌드 환경은 Windows 10·Visual Studio 2017이며 예제 텍스트 추출은 첫 구역만 대상으로 한다. Apache-2.0 표기. [원저자 저장소](https://github.com/hancom-io/hwpx-owpml-model) | Python 기본 의존성보다는 구조 확인용 자료로 활용한다. 예제 결과를 전량 추출로 취급하지 않는다. |

## 형식에서 확인한 필수 구분

- **HWP5**: Compound File 안의 `FileHeader`와 `BodyText/Section*`를 읽는다. 헤더에는 버전과 압축·암호·배포용·DRM 플래그가 있다. 압축된 스트림은 압축 해제 후 레코드를 해석한다. 본문 레코드의 계층으로 문단·표·셀 관계를 복원해야 한다. 표는 행·열 수를, 셀은 행·열 주소와 행·열 병합 수를 가진다. 단순 텍스트 연결이나 미리보기 텍스트는 이 정보를 대신하지 못한다. HWP3는 HWP5와 별도 구조이므로 `.hwp` 확장자만으로 HWP5 지원을 선언하면 안 된다. [한컴 HWP5 명세 §3, §4.1, §4.3.9.1, 표 75·79·80](https://cdn.hancom.com/link/docs/한글문서파일형식_5.0_revision1.2.pdf)
- **HWPX**: `mimetype`으로 형식을 확인하고, `content.hpf`의 spine 순서로 본문을 읽는다. 문단·run·텍스트의 계층이 있으며 암호 정보는 `META-INF/manifest.xml`에 담길 수 있다. [한컴 구조 설명](https://tech.hancom.com/hwpxformat/)
- **HWPX 표 주소**: 한컴 개발자 포럼 답변은 표 셀 `hp:tc`의 `hp:cellAddr`에 있는 `rowAddr`·`colAddr`가 실제 위치에 맞아야 함을 설명한다. 따라서 XML에 나타난 텍스트 순서만으로 셀 위치를 대신하는 설계는 피해야 한다. [한컴 개발자 포럼](https://forum.developer.hancom.com/t/hwpx-xml/2416/2)

## 유지상태·라이선스 관찰

- olefile 원저자 README의 최신 News 항목은 **0.47, 2023-12-01**이다. 순수 Python·추가 의존성 없음으로 설명한다. 자체 코드의 재배포 조건과 기반 PIL 코드의 고지 조건이 함께 명시되어 있다. 정확한 조건은 원문을 유지해 의존성 기록에 반영한다. 이 관찰은 최근 커밋이 없다는 판정이나 프로젝트 Python 버전에서의 실행 검증이 아니다. [olefile README·License](https://github.com/decalage2/olefile)
- pyhwp README는 **AGPLv3 또는 이후 버전**, Python **2.7·3.5~3.8**을 기재한다. CHANGELOG는 **0.1b16 unreleased** 아래 2023년 의존성 보완, 그 아래 **0.1b15 (2020-05-30)**를 기재한다. 이로부터 현대 Python 호환성·배포 상태를 확인할 추가 작업이 필요하다고 판단한다. 최신 커밋 날짜나 패키지 설치 가능성은 이번 조사에서 확정하지 않았다. 라이선스 명칭 확인이며 결합·배포의 법적 결론은 아니다. [README](https://github.com/mete0r/pyhwp), [CHANGELOG](https://github.com/mete0r/pyhwp/blob/master/CHANGES)

## 후속 구현의 검증 조건 제안

아래는 조사에서 도출한 검증 고려사항이다. 최종 지원 경로와 사람 검토 정책은 결정 티켓을 따른다.

1. 공통 입력은 원본 식별자, 구역·표 식별자, 셀 좌표, 병합 범위, 셀 안 문단 순서를 보존하는 표 격자로 만든다. 표 밖 제목·문단도 별도 보존해 금액 단위·기관·기간 등 문맥을 잃지 않도록 한다.
2. 여러 구역·여러 표·병합 셀·셀 안 여러 문단·표 안 중첩 표를 각각 검증한다. 병합 표현을 일반 셀로 펼칠 때는 원래 병합 범위와 원문을 남겨, 병합 셀 복제로 지출 레코드가 중복 생성되지 않게 한다.
3. 구조 읽기·표 복원·헤더 매핑·레코드 추출을 별도 성공 조건으로 둔다. 구조를 못 읽는 파일은 LLM에 바로 넘길 수 있는 정상 표 입력이 아니다.
4. HWP3, 암호·DRM·배포용, 손상, 이미지 기반 내용 등 자동 경로가 처리하지 못한 경우를 구별해 원본별 미해결로 남긴다. 이번 HWP·HWPX 지원 결정이 모든 하위 버전·보호 문서의 자동 해독을 뜻하지는 않는다.
5. 대표 실제 원본으로 재현 가능한 표·셀 대조를 통과한 후 지원 완료를 선언한다. 실제 원본 대조 결과를 남겨야 하며 합성 fixture나 기존의 다른 형식 표본으로 이를 대신할 수 없다.

## 비교한 변환 경로

| 경로 | 장점 | 제약과 확인할 점 |
| --- | --- | --- |
| 기존 HWP 파서 활용 | 기존 형식 해석 코드를 이용해 개발량을 줄일 가능성이 있다. | pyhwp는 HWP5용이며 HWPX를 별도로 처리해야 한다. 현재 프로젝트 Python과 실제 원본의 표 보존을 검증하지 않았다. [원저자 문서](https://github.com/mete0r/pyhwp) |
| 한글 프로그램 자동 변환 후 파싱 | 형식 해석을 설치된 한글에 맡겨 자체 파서 범위를 줄일 수 있다. | 한글 설치와 자동화 환경이 필요하며 파일 접근 시 보안 승인 메시지 등을 처리해야 한다. 변환 가능 형식은 한글의 문서 필터에 따라 다르다. [오토메이션 안내](https://developer.hancom.com/hwpautomation), [SaveAs 안내](https://forum.developer.hancom.com/t/saveas/660) |
| 사람이 변환 후 파싱 | 자동화 개발 없이 특이한 원본에 개별 대응할 수 있다. | 파일 수와 재수집 횟수에 따라 작업량이 증가한다. 원본 열·표 구조 보존 여부와 원본 대비 누락·중복을 확인해야 한다. 이는 작업 방식에서 도출한 판단이며 소요 시간이나 성공률 실측은 아니다. |

자동화 편의성이나 문서 열기 성공은 레코드 추출 정확성을 보증하지 않는다. HWP/HWPX 원본을 외부에 보관하고 표·셀 위치와 연결한 실제 시험 변환이 별도로 필요하다.
