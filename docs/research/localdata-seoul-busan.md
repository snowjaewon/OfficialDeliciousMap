# 서울·부산 인허가 자료: 개방자치단체코드·수집 절차 조사

- 이슈: [#5 서울·부산 인허가 데이터 코드·절차 조사](https://github.com/snowjaewon/OfficialDeliciousMap/issues/5) (지도 #1의 자식)
- 조사일: 2026-09-09
- 목적: 서울(25개 자치구)·부산(16개 구·군)의 폐업 대조와 좌표 보강(지오코딩 실패 상호)에 인허가 자료를 쓰기 위해 필요한 것 전부 — 코드 표, 요청 형태, 키 발급, 호출 한도, 좌표계, 업종 범위.

## 0. 한 줄 결론

- **localdata.go.kr 은 2026-04-16 자로 문을 닫았다.** 인허가 자료는 공공데이터포털(data.go.kr)의 `행정안전부_식품_○○ 조회서비스`(REST, `apis.data.go.kr/1741000/{slug}/info`)로만 받는다. 목업이 쓰던 엔드포인트가 바로 이것이다.
- 개방자치단체코드 표는 아래 §2에 있다. **서울 25개 구는 이번 조사에서 키 없이 독립 검증했고**(서울 열린데이터광장 sample 엔드포인트), 부산 16개는 목업이 2026-08-21 주소 대조로 얻은 값이다(이번엔 재검증 못 함 — 착수 시 §4의 절차로 1분이면 재확인된다).
- 좌표계는 **EPSG:5174** — 이제 추정이 아니라 **API 문서에 명시**돼 있다. 그래도 §5의 실측 절차는 남긴다.
- 키는 data.go.kr 활용신청 → **자동승인**. 개발계정 **일 10,000회/서비스**. 서울 3업종 전량은 약 4~5천 회라 하루 안에 들어온다.

### 공식 코드표는 없다

- 옛 localdata.go.kr 은 "OPEN API 예제소스/라이브러리 zip 안의 자치단체코드목록 엑셀"로만 제공했고(활용문의 게시판 답변), 그 사이트가 닫혔다.
- data.go.kr 에 개방자치단체코드 단독 데이터셋은 검색되지 않았다. 행정표준코드(code.go.kr)의 법정동·행정기관코드와는 **다른 체계**다(서울 종로구 법정동코드 1111000000 vs 개방코드 3000000).
- 그래서 검증의 1차 근거는 **API 응답 자체**(주소 대조)다.

### 요청 형태 (Swagger 원문)

```
GET https://apis.data.go.kr/1741000/general_restaurants/info
  ?serviceKey={디코딩 키}         # 필수. "공공데이터포털에서 받은 인증키"
  &pageNo=1                       # 필수
  &numOfRows=100                  # 필수. "한 페이지 결과 수(max: 100)"  <- 목업 실측과 일치
  &returnType=json                # 선택. json | xml
  &cond[OPN_ATMY_GRP_CD::EQ]=3000000      # 개방자치단체코드
  # 그 밖의 조건(선택):
  #  cond[ROAD_NM_ADDR::LIKE]=서울특별시   도로명주소 포함   <- 코드 역추적에 쓰는 것
  #  cond[BPLC_NM::LIKE]=…                 사업장명 포함
  #  cond[SALS_STTS_CD::EQ]=…              영업상태코드 일치
  #  cond[LCPMT_YMD::GTE|LT]=YYYYMMDD      인허가일자
  #  cond[DAT_UPDT_PNT::GTE|LT]=YYYYMMDDHHMMSS  데이터갱신시점
```

`cond[…]` 값은 URL 인코딩한다(`urllib.parse.urlencode`). 목업 메모: **값에 공백이 들어가면 0건**.

두 번째 경로 `/history`("데이터 이력조회")는 `cond[BASE_DATE::EQ]`(데이터기준일자) 와 `cond[OPN_ATMY_GRP_CD::EQ]` 가 **필수**다 — "해당 일자기준의 상태값"을 준다. 2026 상반기 고정 데이터라면 폐업 대조 기준일을 이걸로 고정하는 선택지가 있다(미검증, 필요 시 실측).

키 없이 호출하면 HTTP 403 + `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(returnReasonCode 30), 없는 슬러그는 HTTP 400 + `NO_OPENAPI_SERVICE_ERROR`(코드 12) — 직접 확인. 목업의 "엔드포인트는 에러코드로 찾는다" 기법이 지금도 유효하다.

페이지에 실린 결과코드 표: `-1` 시스템 내부 오류 · `-2` 파라미터 부적합 · `-3` 등록되지 않은 서비스 · `-4` 등록되지 않은 인증키 · `-5` API 서버 오류 · `-9` 종료된 서비스 · **`-10` 트래픽 허용 횟수 초과** · `-11` 필수 파라미터 누락 · `200` 성공.

### 503 과 재시도

- 포털 문서에는 503 언급이 없다. 목업 실측: "503(Service Unavailable)이 **수백 쪽에 한 번꼴**", 잠깐 쉬면 다음 시도에 온다. 울산 첫 수집에서 503 을 만난 쪽에서 `break` 해 중구 15/108쪽·남구 85/185쪽에서 멈췄고 2만여 건이 빠져 '확인 불가 32%'(정상 8~9%)가 났다.
- 목업의 대응이 지금 기준으로도 맞다: **쪽 단위 재시도 4회(1→2→4→…초 backoff), 실패 쪽은 건너뛰고 계속, 끝에 자치구별 `받은 건수/totalCount` 출력, 덜 받은 조각은 저장하지 않음, 자치구×업종 조각 저장으로 이어받기.** 서울처럼 큰 도시는 조각 저장이 없으면 중간에 끊겼을 때 처음부터다(목업이 서울 16개 구를 받아 놓고 잃은 사례).

### 데이터 신선도

- 서비스 페이지: 등록일 2025-11-27, 수정일 2026-08-25. 파일데이터 쪽 설명은 "수시 (자동 갱신)", 휴게음식점 파일 설명은 "2일 전 자료를 매일 반영".
- 서울 열린데이터광장 미러는 "매일", "3일전 자료".

## 4. 절차 메모 (도시마다 한 번)

목업 절차(HANDOFF.md "폐업 대조 · 인허가 좌표")를 새 저장소의 파이프라인 용어로 옮긴 것. 코드는 새로 쓴다.

1. **코드 역추적(부산은 필수, 서울은 확인용)**
   `cond[ROAD_NM_ADDR::LIKE]=부산광역시` 로 800~1,200건(8~12쪽) 받아 `OPN_ATMY_GRP_CD` ↔ `ROAD_NM_ADDR` 2번째 토큰을 다수결. 16/16 (25/25) 이 안 나오면 표본을 늘린다. 시도 접두는 도시마다 달라(광주 '전남광주통합특별시') 접두는 보지 말고 자치구 토큰만 본다. 결과를 도시 레지스트리의 `licence_codes` 에 넣고 §2 표와 대조.
2. **수집**: 자치구 × 업종(일반음식점·휴게음식점·제과점영업) 전량. `numOfRows=100`, 조각 저장, 503 재시도, 끝에 `받은/총건수` 출력. 서울은 반나절, 부산은 그 절반.
3. **폐업 대조**: 마커의 상호+자치구로 인허가 레코드를 찾고 `SALS_STTS_NM`/`DTL_SALS_STTS_NM`/`CLSBIZ_YMD` 로 폐업 표시. '확인 불가' 비율이 8~9% 를 크게 넘으면 수집 손실을 먼저 의심한다.
4. **좌표 보강**: 지오코딩에 실패한 상호 중 인허가에 있는 것은 `CRD_INFO_X/Y` 를 EPSG:5174 → WGS84(EPSG:4326)로 변환해 마커로 올린다(pyproj `Transformer.from_crs("EPSG:5174","EPSG:4326",always_xy=True)`). 인허가 업종으로 카테고리도 복원(일반음식점→음식점, 휴게음식점·제과점→카페·디저트).
5. **좌표계 검증**(§5) 을 도시마다 한 번 돌리고 결과를 기록.

캐시·열쇠·결과 파일은 전부 도시별로 둔다(광주 인허가로 대전을 대조한 사고 방지).

## 5. 좌표계: EPSG:5174

- **공식 명시**: 일반음식점·휴게음식점·제과점·모범음식점 조회서비스 설명과 파일데이터 설명 모두 "**좌표계 : 보정계수 안들어간 Bessel 중부원점TM(EPSG:5174)**". 서울 열린데이터광장도 "중부원점TM(EPSG:5174) 좌표계에 따른 해당위치의 좌표정보이며 위경도 좌표는 제공하고 있지 않음".
- **목업 실측**(도시별 네이버 좌표와의 거리 중앙값): 대전 5174=8m / 2097=321m / 5181=320m. 광주 26m(2097 263m·5181 317m). 울산 5m · 대구 14m. 네 도시 다 5174.
- **재확인 방법**(도시마다): 폐업 대조가 '영업 중'으로 확정한 짝(네이버 좌표와 인허가 좌표를 둘 다 아는 마커) 수십 곳에 대해 EPSG:5174·2097·5181 세 가지로 변환한 뒤 거리 중앙값을 비교. 5174 가 한 자릿수~수십 m 로 확연히 작아야 한다. "보정계수 안 들어간"이라는 문구가 뜻하듯 Bessel→WGS84 변환 파라미터 차이로 도시별 수 m~수십 m 오차는 정상.
- 서울 표본 값 예: X 198810.77, Y 448800.97(용산구) — 중부원점(원점 127°E·38°N, false easting 200,000 / northing 500,000 계열)에 부합한다.
