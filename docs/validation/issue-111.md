# 이슈 #111 조회 캐시 한 번 읽기 실측

2026-09-13, Windows 11 · Git Bash · Python 3.12.10 · uv 0.12.3.
범위: [조회 캐시를 실행마다 한 번만 읽는다 #111](https://github.com/snowjaewon/OfficialDeliciousMap/issues/111).
대상은 `geocode` 단계의 조회 캐시 읽기 경로(`lookup.resolve()`)다. 쓰기 경로는 범위 밖이다.

## 0. 이슈가 인용한 근거를 정정한다

이슈 본문의 "근거 (실측)" 표는 도시 전체 1차 10분 24초·2차 39분 11초의 출처로
`docs/validation/issue-99.md`를 가리킨다. **그 문서에 두 수치가 없다.** issue-99.md가 적은 시간은
기관별 `fetch` 합계 3분 38초, Gemini 경로 28초, gitleaks가 걸린 커밋 34분·36분뿐이고
`geocode` 단계의 실행 시간은 어디에도 없다. 그래서 이 문서는 그 두 수치를 대조 기준으로 쓰지 않고
같은 기기·같은 입력에서 변경 전후를 직접 잰 값으로 대체한다.

## 1. 무엇을 쟀나

커밋된 산출물을 덮지 않도록 `data/gwangju`·`data/_shared`·`data/manual`을 임시 폴더로 복사하고
`--data-root`로 그 사본을 지정했다. 원본은 저장소 밖 `deliciousmap-raw`를 그대로 읽는다.

```text
uv run python -m deliciousmap geocode --city gwangju \
  --raw-root <저장소 밖 원본> --data-root <사본>/data --output-root <사본>/out
```

변경 전은 워크트리를 되돌리지 않고 `git archive HEAD src/deliciousmap`으로 꺼낸 트리를
`PYTHONPATH`로 앞에 두어 같은 명령을 돌렸다. 두 실행 모두 같은 사본에서 새로 시작한다.

### 이 재실행이 실제로 타는 경로

네트워크를 쓰지 않는 계측으로 먼저 확인한 값이다.

| 항목 | 값 |
| --- | --- |
| 파싱된 레코드 | 9,720 |
| 그중 식당 판정 | 6,886 |
| 조회 경로에 들어간 레코드 | 6,886 (`geocode-input.json`이 없어 전부 `not_supplied`) |
| 고유 조회 키 | 3,122 |
| 캐시 적중 / 미스 | 6,886 / **0** |
| 구성된 제공자 | 네이버 지역검색 1개 (`DATA_GO_KR_KEY`가 없어 인허가는 구성되지 않음) |
| 캐시 파일 | `geocode-lookup-v1.jsonl` 4,195줄 / 11.6MB, 유효 키 4,193 |
| 캐시 1회 파싱 | 0.45초 |

미스가 0이라 두 실행 모두 네이버를 한 번도 부르지 않았다. 비용은 0원이고 쓰기 경로도 타지 않는다.
읽기 경로만 남은 조건이라 이 변경의 효과가 그대로 드러난다.

**`.env`를 실지 않으면 이 측정이 성립하지 않는다.** 이 저장소의 코드는 `.env`를 스스로 읽지 않는다.
키가 없으면 `naver.from_environment()`가 `None`을 주고 제공자가 0개가 되어 `lookup.resolve()`가
캐시를 한 줄도 읽지 않고 돌아온다. 그 상태에서 잰 값(변경 전후 모두 약 48초)은 이 변경과 무관하다.

## 2. 결과

| 실행 | 캐시 파일 전체 파싱 횟수 | 걸린 시간 | 종료 코드 |
| --- | --- | --- | --- |
| 변경 전 (`HEAD`) | 6,886회 예정 | **25분 7초에 미완료** (중단) | 강제 종료 |
| 변경 후 | **1회** | **63초** | 0 |

**변경 전 값은 하한이다.** 25분을 마감으로 두고 돌렸고 그때까지 끝나지 않아 중단했다. 끝까지
갔을 때의 값은 재지 않았다. 산술로는 캐시 1회 파싱 0.45초 × 6,886회 ≈ 52분이 파싱에만 들고,
실제 실행에는 상류 산출물 읽기와 이력 쓰기가 더 붙는다.

변경 전의 파싱 횟수가 조회 경로에 들어간 레코드 수와 같은 이유는 레코드마다 `select_cache()`가
`read_cache()`로 4,195줄을 처음부터 다시 읽기 때문이다. 변경 후에는 `resolve()` 진입에서 한 번
읽고 레코드 루프가 사전만 본다.

확인된 차이는 **63초 대 25분 7초 이상, 24배 이상**이다.

## 3. 판정이 바뀌지 않았다

변경 후 실행이 만든 `geocode.json`은 커밋된 `data/gwangju/geocode.json`과 **바이트 단위로 같다**
(15,039,832바이트, sha256 `e547a505…`). 새 이력 조각이 생기지 않았고 `geocode-lookup-v1.jsonl`도
4,195줄 그대로다. 적중을 적중으로, 재시도를 재시도로 남기는 동작이 그대로라는 뜻이다.

## 4. 완료 기준 대조

| 기준 | 결과 |
| --- | --- |
| 도시 전체 실행에서 조회 캐시 파일을 읽는 횟수가 1이다 | 2절. 줄 파싱은 1회다. `tests/test_naver_lookup_cli.py`의 `test_a_rerun_that_only_hits_reads_the_lookup_cache_once`가 `read_cache` 호출을 세어 고정한다. 파싱과 별개로 봉투의 `dependencies`가 같은 파일을 `file_digest()`로 한 번 더 읽는다(`storage.py`). 이슈가 문제 삼은 `Θ(n·C)` 줄 파싱과는 다른 비용이고 실행당 1회다 |
| 실행 중 새로 얻은 조회가 같은 실행의 뒤 레코드에 적중한다 | `test_a_lookup_found_mid_run_hits_the_later_records_of_the_same_run`. 사전 갱신을 빼면 제공자 호출이 1회에서 2회로 늘어 실패한다 |
| 기존 캐시 적중·미스·재시도·실패 기록 보존 동작이 그대로다 | 3절. `tests/test_naver_lookup_cli.py`·`tests/test_geocoding_cli.py` 49개가 그대로 통과하고 전체 533개도 통과한다 |
| 광주 `geocode` 재실행 시간을 실측해 남긴다 | 이 문서 2절에 63초로 남겼다. 이슈가 인용한 39분 11초는 근거 문서에 없어 0절대로 정정하고, 같은 기기의 변경 전 실측(25분 7초 이상, 미완료)을 대조 기준으로 썼다 |

## 5. 실패하는 테스트를 먼저 썼다는 기록

커밋 이력에 적색 단계가 남지 않아 실행 결과를 여기 옮긴다.

| 단계 | 결과 |
| --- | --- |
| 구현 전, 읽기 횟수 테스트 | `AssertionError: assert 3 == 1` — 레코드 3건이면 캐시를 3번 파싱했다 |
| 사전은 넣고 실행 중 갱신만 뺀 상태 | `AssertionError: assert 2 == 1` — 같은 상호를 제공자에게 두 번 물었다 |
| 갱신까지 넣은 최종 상태 | 두 테스트 모두 통과 |

두 번째 줄이 완료 기준 2를 실제로 고정한다는 근거다. 사전 갱신을 지우면 그 테스트가 다시 깨진다.

## 6. 남은 제한

- **쓰기 경로는 그대로다.** `append_cache_entries()`가 미스마다 파일 전체를 다시 읽고 마지막
  조각을 다시 쓴다. 이번 재실행은 미스가 0이라 타지 않았고, 새 상호가 많은 실행에서는 그 비용이
  남는다. 모아서 쓰는 설계는 중간 실패 시 조회를 잃고 워크트리 여럿이 같은 revision에서 부딪히므로
  이슈가 범위에서 뺐다.
- **메모리를 실측하지 않았다.** 사전이 값까지 들고 있어 캐시가 커지면 상주 메모리가 는다.
  이번 규모(4,195항목)에서 실행이 끝까지 갔다는 것만 확인했고 피크는 재지 않았다.
- **`retry_failed`의 실행 내 재시도 횟수는 정하지 않았다.** 켜져 있으면 같은 키가 나올 때마다
  다시 묻는 동작이 변경 전과 같다. "이번 실행에서 이미 재시도한 키"를 따로 기억할지는 별도 결정이다.
- **다른 세션이 같은 파일에 쓰면 실행 중에는 보이지 않는다.** 사전이 시작 시점의 내용만 든다.
  그 경우 이어 쓰기가 같은 revision을 만나 `cannot overwrite cache history`로 멈춘다.
  조용히 덮지는 않는다.
