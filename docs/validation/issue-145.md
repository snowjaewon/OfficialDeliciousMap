# Issue #145 검증 — 울산 HTML 표 집행내역

검증일 2026-09-14. 원본은 저장소 밖 `C:\Users\설재원\deliciousmap-raw`(`--raw-root`)에 두었고
저장소에 옮기지 않았다. 모델은 쓰지 않았다(`GEMINI_*` 없이 실행). 결정은
[ADR-0008](../adr/0008-declare-html-table-mappings.md)에 있다.

## 실측한 게시판

메뉴 진입점 `/u/rep/contents.ulsan?mId=…`이 넘겨주는 주소를 그대로 등록했다. 내용은 경로와 `se`가,
화면 제목은 `mId`가 정한다. 옛 `expenses-economic`(`mId=…001`, `se` 없음)은 기본값 `se=3`이라

## 원본 보존과 해석

- 원본은 상세 쪽(중구는 회계연도 목록 쪽) 응답 전체이고 컨테이너는 `html`이다. 스크래퍼가 `.html`을
  밝힌 게시판에서만 HTML을 원본으로 받는다. 첨부 게시판의 HTML 오류 쪽은 전처럼 거부한다.
- 시청·동구 게시글 번호는 사용일자(`20260630`)다. 목록 쪽·순번은 새 게시글이 오면 밀려서 쓰지 않는다.
  옛 쪽·순번 번호로 쌓인 목록 색인은 저장소 밖에서 `listing.pre-145.jsonl`로 이름을 바꿔 두었다.
- 헤더 매핑은 레지스트리 선언(`DeclaredTable`)이다. 첫 행이 선언과 같은 표 하나에만 적용하며, 이번
  실행의 HTML 원본은 모두 선언과 헤더가 같았다(`declared header not found` 0건).
- 하루치 원본마다 제목의 `(N건)`과 코드가 센 후보 수를 대조했다. 시청 대상 원본 501개와 동구 25개가
  모두 같았다. 중구 목록의 `총게시물 198`도 후보 198과 같다.

### 시청 천원 표의 원 단위 행

| 구간 | 행 수 |
| --- | ---: |
| 100 미만 | 997 |
| 100~999 | 2,642 |
| 1,000~9,999 | 7 (최대 3,500 — 70명 행사) |
| 10,000 이상 | 42 (48,000~450,000, **모두 부서장 게시판**) |

3,500과 48,000 사이에 값이 없고, 10,000 이상의 42행은 4~10명의 한 끼로 보면 원 단위다(목업이
7건이라 적은 것보다 많다). 기준값 `THOUSAND_WON_CEILING = 10,000(천원)`은 이 공백 안에 둔다. 42행이
걸린 **부서장 원본 34개(날)**는 곱하지도 원으로 고쳐 읽지도 않고 `validation_failed`(`amount_unit`)로
남겼다. 그 원본의 후보 수는 센다.

### 동구 금액 빈 행

동구 원본 2개(2026-01-28, 2026-02-09)에 금액 칸이 빈 채 첨부만 단 행이 있어 `validation_failed`

## 도시 산출물

도시 `fetch.json`은 여섯 기관의 `fetch.json`을 레지스트리 순서로 이어 붙여 만들었다(#146과 같은
방법). 이 방법으로 커밋된 도시 `fetch.json`이 먼저 그대로 재현되는 것을 확인했다(`spent_on` 칸만
뺀 비교). 남구·북구·울주군 기관 산출물은 다시 만들지 않았다.

| 도시(`data/ulsan`) | 전 | 후 |
| --- | ---: | ---: |
| 원본 / 받지 않은 게시글 | 873 / 21,863 | 1,575 / 19,867 |
| 헤더 매핑 / 그중 선언 / 미해결 원본 | 30 / 0 / 568 | 521 / 491 / 622 (`model_not_configured` 509, `no_table` 63, `validation_failed` 36, `unsupported_format` 14) |
| 대상 원본 / 통과 원본 | 594 / 26 | 1,139 / 517 |
| 기간 밖 원본(`declared_out_of_range`) | 279 | 436 |
| 레코드 | 124 | **3,425** |
| 재게시 집계 | 0 | 합치지 않음 25지출·26레코드 |
| classify | 식당 3, 비식당 1, 판단 보류 120 | 식당 74, 비식당 85, 판단 보류 3,266 (`model_not_configured` 3,174) |
| geocode | `경복궁` 사람 확인 1, 보류 2 | `경복궁` 사람 확인 1, `missing_address` 73 |
| build | 124 레코드, 마커 1 | 3,425 레코드, 마커 1 |

- 합치지 않은 25지출은 같은 날·같은 상호·같은 금액이 두 원본에 한 번씩 실린 것이다. 대부분 여러
  게시판의 경조금 50,000원(`-` 또는 `개인(성명 비공개)`)이고, 한 쌍이 한 건만 겹친 것은 재게시의 근거가
  아니라 ADR-0004대로 남겼다.
- 식당 74건은 공통 분류 캐시가 이미 판정한 상호다. 원본에 주소가 없어 모두 `missing_address`로
  보류됐고 새 마커는 없다. 판단 보류 3,266건의 분류와 지오코딩 사람 확인은 이 이슈의 범위 밖이다.
- 기관 산출물(`ulsan-city`, `ulsan-junggu`, `ulsan-donggu`)도 `headermap`→`build`를 다시 냈다. 기관
  `geocode`는 네이버·인허가 키를 넣고 실행해 exit 0이다. 중구 기관 산출물은 옛 스키마(parse v4, build
  v8)라 저장소 규칙대로 옛 판이 `history/`에 보관됐다.

## 계약과 호환

`SourceRef.spent_on`, 컨테이너 `html`, `HeaderMap.declared`는 모두 선택 칸이다. 기존 v4 `fetch.json`과
v2 `headermap.json`이 그대로 읽히므로 스키마 버전은 올리지 않았다. 올리면 광주 수집을 다시 해야 하지만
내용은 바뀌지 않는다. 다시 만든 울산 `fetch.json`의 출처에는 `"spent_on": null`이 붙는다.

## 리뷰 뒤 수정

코드 리뷰(기준·명세 두 축)에서 나온 것 가운데 다음을 고쳤다(`1018229`, `bdeb6d8`). 시청 이전
게시판이 게시글 번호·집행일을 목록 칸 대신 여는 상세 키에서 읽게 했다. 열 이름 표시가 붙은 빈
요소가 숨김을 닫지 못하던 것을 고쳤다. 천원 기준을 선언한 표에만 걸고, `is_html`을 grid로 옮겼다.
수정 뒤 도시와 세 기관의 `headermap`·`parse`를 다시 돌려 `headermap.json`·`parse.json`·`records.csv`
12개 파일의 해시가 전과 같음을 확인했다. fetch는 다시 돌리지 않았다. 수집 기록 672줄(시청 다섯
게시판·동구 구청장)의 게시글 번호를 그 줄에 남은 상세 주소의 `useDe`·`ymd2` 키와 대조해 모두 같은
날임을 확인했으므로, 새 규칙으로 다시 수집해도 게시글 번호·집행일은 바뀌지 않는다.

## 남은 제한

- 부서장 원본 34개(원 단위 행)와 동구 원본 2개(금액 빈 행)는 미해결이다. 사람이 원본을 대조해 확정할
  길(`sources.jsonl`의 사유)은 지금 `merchant_blank`·`total_mismatch`뿐이라 사유를 더할지는 따로 정한다.
- 부서장 목록의 `202-12-28` 행 때문에 그 게시판은 매 수집마다 `adapter-failed` 경고로 끝나고, 실패
  이후 쪽(2020년 이전)의 받지 않은 게시글 수를 세지 못한다.
- 받지 않은 게시글 수는 장부(`fetch.json`)에 기관 합계 하나로만 남는다. 위 표의 게시판별 수는 저장소
  밖 목록 색인에서 센 것이고, 원본·레코드의 게시판별 수는 `fetch.json`의 `board`와 `parse.json`을
  원본 해시로 이어야 나온다. 장부 계약에 게시판별 칸을 더할지는 따로 정한다.
- 시청 이전 게시판은 대상 연도의 상세만 열고 목록은 끝까지 훑는다(받지 않은 게시글 수를 세기 위해).
  시청 한 번의 수집이 약 18~27분 걸린다. 중단한 수집은 받은 날의 상세를 다시 요청하지 않고 이어진다.
- 중구 회계연도 목록은 한 번 받으면 다시 받지 않는다(ADR-0008). 2026년 목록은 2026-06-30까지 차
  있어 이번 제출 기간에는 모자람이 없다.
- 새 레코드 3,301건의 비식당 판별(모델)·지오코딩 사람 확인은 하지 않았다. 지도 마커는 그대로 1개다.
- 지도 타일·실기기 확인은 하지 않았다.
