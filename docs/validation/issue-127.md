# 상호 끝의 `외 N`을 떼고 조회한다 (#127)

2026-09-14 실행. 상호 칸 끝에 이름 없이 수만 적은 꼬리말을 떼고 조회한 기록이다. 범위는
광주 도시 단위 실행(`geocode` → `closure` → `build`)이며 수치는 커밋된 산출물에서 다시 셀 수
있다. **좌표를 새로 받은 레코드는 0건이다.** 조회가 되기 시작한 것과 좌표를 받은 것은 다르며
이 문서는 그 둘을 나누어 적는다.

## 1. 떼는 것과 떼지 않는 것

규칙은 `src/deliciousmap/merchants.py` 하나가 소유한다. 조회 질의어(`lookup.resolve`)와 근거와
맞춰 볼 이름(`identity.decide_identity`)이 같은 이름을 쓴다. **레코드의 원본 표기는 바뀌지 않는다.**

| 대상 | 예 | 조회 이름 | 이름 없는 업소 |
| --- | --- | --- | --- |
| `외` + 수 | `스타벅스 외 1` | `스타벅스` | 1곳 |
| 세는 낱말 | `명태어장 외 1곳`·`진보쌈외 1개소`·`수림정 외 1명`·`민족감자탕 외 1개` | 앞의 이름 | 1곳 |
| 공백 없는 표기 | `순창민물매운탕외1개소` | `순창민물매운탕` | 1곳 |
| 수도 없는 맨끝 `외` | `낙지촌 외` | `낙지촌` | **알 수 없음** |

떼지 않는 것도 규칙으로 고정했다(`tests/test_merchants.py`).

| 두는 것 | 예 | 이유 |
| --- | --- | --- |
| 이름 가운데·앞의 `외` | `외갓집 순두부 본점` | 상호의 글자다 |
| 공백 없는 맨끝 `외` | `광주 농협로컬푸드직외` | 낱말이 잘린 것인지 꼬리말인지 가를 근거가 없다 |
| 떼면 이름이 남지 않는 표기 | `외 1` | 조회할 첫 업소의 이름을 지어내지 않는다 |
| 이름을 다 적은 합쳐 적은 상호 | `나주곰탕, 홀브라운외` | 가르는 일이며 [#117](https://github.com/snowjaewon/OfficialDeliciousMap/issues/117) 범위다 |

수를 적지 않은 표기의 업소 수는 **알 수 없음**으로 남기고 0곳으로도 1곳으로도 적지 않는다.
`records.json`은 `null`, 집계는 `uncounted_records`로 따로 센다.

## 2. 광주 176건이 달라진 것 — 후보 0건 → 161건, 좌표 0건

식당으로 가른 레코드 6,834건 가운데 꼬리말이 붙은 것은 **176건, 고유 상호 156개**다.
이슈가 실측한 수와 같다.

| 사유 | 이전 | 이후 |
| --- | --- | --- |
| `no_candidates` 후보 없음 | 175 | **15** |
| `missing_address` 주소 근거 없음 | 1 | **161** |
| 좌표 확보 | **0** | **0** |

**160건이 `no_candidates`에서 `missing_address`로 옮겼다.** 조회가 후보를 주기 시작해
(고유 상호 142개, 후보 507건) 사유가 "그런 업소가 없다"에서 "이 후보가 그 업소인지 가릴
독립 근거가 없다"로 바뀐 것이다.

**그런데도 좌표는 0건이다.** 광주 원본에는 주소 칸이 없어 자동 채택이 요구하는 독립 근거
(상호·지점·주소)가 성립하지 않는다. 광주에서 마커가 된 774건은 모두 사람이 확인한
`human_confirmed`이며, 이번 161건도 같은 경로로만 마커가 된다
([지오코딩의 사람 확인](../geocoding.md#사람-확인), [#64 검증](issue-64.md)).
**이 변경이 한 일은 그 확인을 할 후보를 만든 것까지다.** 확인은 이 이슈 범위가 아니다.

남은 15건은 꼬리말을 떼도 후보가 없다. 원본이 **상호 자체를 잘라 적은 것**이 대부분이다.

```text
메가엠지씨커피광주운외 1      텐퍼센트스페셜커피광외 1
투썸플레이스 두암타외 1        (주)대성콩물(일곡지외 1
```

이름이 잘린 상호는 근거 자료와 대조해야 하므로 [상호 복원](../restoration.md) 범위다.
떼기만으로 끝나지 않는다는 것이 이 15건으로 드러난다.

## 3. 이름 없는 업소가 남는 자리

둘째 업소는 이름이 없어 **영영 마커가 되지 못한다.** 그 사실을 수로 남긴다.

| 자리 | 값 |
| --- | --- |
| 장부(`records.json`의 `unnamed_companions`) | 레코드마다 곳 수. 꼬리말이 없으면 `0`, 수를 적지 않았으면 `null` |
| 장부 화면(`app.js`) | `이름 없는 동행 업소 1곳` / `이름 없는 동행 업소 수 미상` |
| 자료 범위 대화상자 | 아래 한 줄 |

```text
상호 끝에 이름 없이 수만 적은 249건이 밝힌 이름 없는 업소 247곳은 조회할 이름이 없어
지도에 오르지 못합니다. 그 가운데 8건은 원본이 수도 적지 않아 몇 곳인지 알 수 없습니다.
```

장부가 세는 249건은 **판정 대상이 아닌 레코드까지 담은 수**다. 176건만 세면 장부에 보이는
나머지가 없는 것처럼 읽힌다.

| 분류 | 레코드 | 이름 없는 업소 | 수 미상 |
| --- | --- | --- | --- |
| 식당 | 176 | 178곳 | 3건 |
| 판단 보류 | 61 | 57곳 | 4건 |
| 비식당 | 12 | 12곳 | 1건 |
| **합계** | **249** | **247곳** | **8건** |

업소 둘에 걸친 지출의 금액은 [ADR-0007](../adr/0007-do-not-split-unallocated-amounts.md)을
따라 배분하지 않는다. 이 변경은 금액에 손대지 않았다.

## 4. 기존 확정 판정이 바뀌지 않았다는 것

`identity.POLICY_VERSION`을 `identity-2`에서 `identity-3`으로 올렸다. 판정이 레코드에서 읽는
이름이 달라졌으므로 이전 판정을 그대로 재사용하면 안 된다. 6,834건을 모두 다시 판정했고
그 가운데 **달라진 것은 160건뿐이며 모두 꼬리말 레코드다.**

| 확인 | 값 |
| --- | --- |
| 판정이 달라진 레코드 | 160건 (모두 `no_candidates` → `missing_address`) |
| 꼬리말이 없는 레코드 중 달라진 것 | **0건** |
| `matched`·`human_confirmed`가 달라진 것 | **0건** |
| 확정 성공 | 774건 → 774건 |
| 마커 | 32개 → 32개, `business_id` 전부 동일 |

판정 이력은 앞 조각을 고치지 않고 `geocode-history-v2.007.jsonl`(17.2MB)을 새로 열어 쌓았다.
모든 조각이 20MB 이내다(ADR-0001).

조회 캐시는 67줄이 늘었다. 뗀 이름 142개 가운데 상당수가 꼬리말 없는 레코드의 조회로 이미
캐시에 있었기 때문이다. 같은 이름을 두 번 묻지 않는다.

## 5. 실행한 명령

저장소 루트에서 Git Bash·PowerShell 공통.

```text
uv run --env-file .env python -m deliciousmap geocode --city gwangju
uv run --env-file .env python -m deliciousmap closure --city gwangju
uv run --env-file .env python -m deliciousmap build --city gwangju
uv run pytest
uv run ruff check .
uv run ruff format --check .
node --test tests/site_behavior.test.js tests/measure_map.test.js tests/service_worker.test.js
```

LLM 호출은 0회이며 공통 예산 장부는 한 줄도 늘지 않았다. 외부 호출은 네이버 지역검색뿐이다.

## 6. 하지 않은 것

- **좌표 확보는 0건이다.** 161건은 후보를 얻어 사람 확인 대상이 됐을 뿐이다. 확인을 쓰고
  마커를 내는 것은 [#64](issue-64.md)·[#99](issue-99.md)의 기준을 따르는 별도 작업이다.
- **다른 도시는 세지 않았다.** 광주 실측만 근거로 한다.
- **`classify`는 다시 돌리지 않았다.** 비식당 판별은 지금도 원본 표기 그대로를 본다.
  좌표 판정 176건은 모두 이미 식당으로 갈린 뒤라 이번 변경이 그 판별을 건드리지 않았지만,
  꼬리말이 붙은 **판단 보류 61건**은 뗀 이름으로 다시 판별하면 달라질 수 있다. 재판별은 LLM
  호출을 새 키로 일으키므로 이 이슈 범위가 아니다.
- **기관별 작업 산출물(`data/gwangju/orgs/*`)은 다시 돌리지 않았다.** 배포되는 것은 6개 기관
  레코드를 모두 담은 도시 실행이다. 기관 실행 다섯 곳은 `identity-2` 판정을 담은 채 남으며,
  그 가운데 넷(`gwangju-dong`·`gwangju-gwangsan`·`gwangju-nam`·`gwangju-seo`)은 이 변경
  **전부터** `classify.json`이 `parse.json`보다 낡아 있었다. 다시 돌리려면 저장소 밖 원본과
  `classify`부터 필요하므로 이 이슈 범위가 아니다.
- **합쳐 적은 상호 549건은 그대로다.** 쉼표·슬래시·`&`·`및`로 둘을 다 적은 표기는
  [#117](https://github.com/snowjaewon/OfficialDeliciousMap/issues/117) 범위다.
