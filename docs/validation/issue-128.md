## 2. 등급 — 조각 후보를 어떻게 읽었는가

표기마다 `merchants.parts`로 조각을 내고(합계 961개), 조각마다 `lookup.request_key`로 지역검색
(`naver-local-1`, limit 5)·인허가(`food-license-2`, limit 100)의 캐시 키를 계산해
`data/gwangju/geocode-lookup-v1*.jsonl`에서 후보를 읽었다. 961조각 × 2제공자의 키가 모두 캐시에
있었다(미스 0). 표기 전체 조회는 레코드가 남긴 `lookup.queries`의 캐시 키를 그대로 읽었다.

- **광주 소재**: 후보 주소가 `registry/gwangju.py`의 `address_prefixes`(`전남광주통합특별시`)로
  시작하는 것. 이 접두는 옛 광주광역시 5개 구뿐 아니라 통합특별시 안의 시·군(목포·여수·나주 등)도
  포함한다. 판정 코드(`identity`)와 같은 기준이라 그대로 썼고, 이 문서의 "광주"는 모두 이 뜻이다.
- **정확 일치**: `merchants.bare_name`이 글자까지 같음. **포함 일치**: `merchants.name_inclusion`.
- 등급 정의는 실행 결정과 같다. 다시 센 표기·레코드 수가 결정의 표(A 298/342 · B 97/112 ·
  C 59/62 · D 13/13 · E 13/17)와 일치한다.
- B의 "광주 후보 있음"은 상호 일치를 요구하지 않는다. B 초안 88표기 가운데 35표기는 한 조각이
  광주 후보는 있으나 정확도 포함도 아닌 경우다(`도미노피자, 꿀씨닭`의 `꿀씨닭`, `돼지고기듬뿍김치찌개,
  할리스북구청점`의 `돼지고기듬뿍김치찌개`). `evidence`에 `광주 후보 N건이나 상호가 다름`으로 적었고
  그 조각에는 `references`가 없다(참조 1건인 줄 89 가운데 35). 결정의 B 수 97이 같은 기준으로 센 값이라
  초안에 넣었으며, 그 조각의 후보는 좌표 판정이 다시 대조한다.

## 3. 초안 규칙

- **조각 이름은 원문 그대로**(앞뒤 공백만 정리). `㈜`·`(사)`·괄호·지점명·`홀브라운외` 같은 표기도
  남긴다. 이름 고치기는 `restore.jsonl`의 일이다. 금액 조각(`96,000원`, `17,500`)만 뗐다.
- **단체명 조각**(`(사)실로암사람들`, `(사)어울림복지재단`)은 그대로 두 업소로 선언했다. 식당 여부는
  `classify`가 가른다.
- **2자 이하 조각**은 그 조각에 정확 일치 광주 후보가 있을 때만 초안(`만선`·`수궁`·`콩샌` 등 41표기),
  없으면 보류(11표기). 천단위 7건의 `리움`은 예외다 — 원본이 업소별 금액을 적은 것 자체가 두 업소의
  근거라 2자 규칙보다 앞선다.
- **천단위 7건의 금액은 배분하지 않았다.** [ADR-0007](../adr/0007-do-not-split-unallocated-amounts.md)은
  이 7건을 배분 예외로 두지만, 확인 줄이 업소별 금액을 받는 계약이 아직 없고([#117 검증 7절](issue-117.md))
  이슈가 남은 제한에서 이름만 확정하기로 했다. ADR과 어긋나는 자리라 7줄의 `evidence`에 그 사정을
  적었다. 예를 들어 `965b37662bc4394e-sheet1-R7`은 원본이 적은 96,000+17,500이 지출 금액 113,500과
  맞아 계약이 생기면 배분할 수 있다.
- **손으로 적은 표기**는 하나다. `배가네동태탕찜전문점 / 엔제리너스 상무D/T점`을 규칙은 3조각으로
  내지만 `D/T`는 드라이브스루 표기 안의 슬래시라 2업소(`배가네동태탕찜전문점`·`엔제리너스 상무D/T점`)로
  적었다. `evidence`에 그 사정을 남겼다.
- **`evidence`** 틀: `에이전트 검토(#128). '<조각>' 인허가 광주 정확 일치 N건·지역검색 M건, ….
  표기 전체 조회 K건. 등급 X(…). 사람의 최종 확인은 이 줄을 담은 PR 검토다`. 후보 없는 조각은
  `광주 후보 0건(갈린 뒤 no_candidates로 남는다)`로 적었다.
- **`references`**: 조각마다 광주 후보 1건. 정확 일치를 먼저, 없으면 포함 일치를 쓰고 인허가를
  지역검색보다 앞세웠다. 같은 등급 안에서는 옛 광주광역시 5개 구 주소의 후보를 먼저 골랐다(후보 수는
  바꾸지 않는다). 천단위 7줄은 후보가 없어 `references`가 비어 있다.
- 줄 순서는 등급 A → B → C → D, 등급 안에서는 고정 목록 순서(레코드 수 내림차순)다. 커밋도 등급별로
  나눴다.

## 5. parse 재실행 — 지출 510건이 레코드 1,020건으로 갈렸다

```text
uv run python -m deliciousmap parse --city gwangju
```

`fetch`·`headermap`은 다시 돌리지 않았다. 아래 수는 재실행 전(`develop` 4422667)과 후의
`data/gwangju/records.csv`를 `record_id`로 대조한 값이다.

| 항목 | 재실행 전 | 재실행 후 |
| --- | --- | --- |
| 레코드 | 9,825 | **10,335** |
| 갈린 지출(`expense_id`, 금액 빈 값 레코드의 부모) | 0 | **510** |
| 갈린 레코드(`amount_krw` 빈 값) | 0 | **1,020** (지출마다 2) |
| 한 업소 확인 레코드(`expense_id` 있고 금액 있음) | 0 | 0 |
| 그 밖의 레코드 | 9,825 | 9,315 — 재실행 전 값과 **글자까지 같다** |
| 지출 총액(`merchants.expense_total`) | 1,351,107,943 | **1,351,107,943** |

- 갈린 지출 510건은 모두 고정 목록의 546건 안에 있고, 목록 밖에서 갈린 지출은 0건이다. 남은 36건이
  4절의 보류다. 기관별로는 북구 198 · 광산구 106 · 시청 87 · 남구 72 · 서구 24 · 동구 23이다.
- 총액이 같은 것이 [ADR-0007](../adr/0007-do-not-split-unallocated-amounts.md)의 확인이다.
  #117 검증이 적은 `1,340,258,343`원은 그때의 산출물(레코드 9,720건) 값이고, 그 뒤 산출물이 바뀌어
  이 브랜치의 재실행 전 총액은 `1,351,107,943`원이다. 비교는 같은 브랜치의 전후로 했다.
- `parse.json`은 두 곳이 바뀌었다. 의존성의 `merchants` 해시(빈 파일 해시 → 448줄 파일 해시)와,
  `payload.sources[*].records`(원본별 레코드 수)가 갈린 지출을 실은 원본 147개에서 합계 510만큼 늘었다.
  `excluded_sources`·`repeated_expenses`·`reporting_period`는 그대로다.
- 기관별 산출물(`data/gwangju/orgs/*/parse.json`)은 손대지 않았다. 도시 산출물이 기관 레코드를 모두
  담으므로 위 수가 전수이고, 기관별 재실행은 `classify` 이후와 함께 후속 PR에서 한다.

## 7. 세는 방법

저장소 루트에서 PowerShell·Git Bash 공통으로 아래가 통과한다.

```text
uv run pytest
uv run ruff check .
uv run ruff format --check .
git diff --check
```

2절·4절의 수는 조회 캐시에서, 5절의 수는 `records.csv`에서 다시 셀 수 있다. 조각 후보는
`deliciousmap.lookup.request_key`(제공자 stub의 `provider`·`interpretation`·`limit`은 `naver.py`·
`licenses.py`의 상수)로 키를 만들어 `storage.LookupCache`에서 읽고, 광주 소재는 `address_prefixes`,
일치는 `merchants.bare_name`·`merchants.name_inclusion`으로 가른다. 5절은 `csv`로 두 판을 읽어
`amount_krw`가 빈 레코드와 `expense_id`를 세고, 총액은 `merchants.expense_total`과 같은 규칙
(금액 없는 레코드는 지출 금액을 한 번만)으로 더한다.
