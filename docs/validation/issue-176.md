## 0. 이번 실행이 따른 결정

1. **게시일 없는 게시글은 제목의 해와 기간으로 가른다** (2026-09-17 사용자 결정). 수성구 원본 461개는
   게시일이 없다. 그래서 `period.exclusion`이 461개 모두를 `posted_out_of_range`로 뺐다. 이슈 본문은
   "제목으로 가른다"고 적었지만 코드는 그렇게 동작하지 않았다(4절).
2. **헤더 매핑은 에이전트 CLI가 판정했다.** [폴백 정책](../specs/header-mapping-fallback.md)의
   `### 헤더 매핑 판정 경로`를 따랐고, 모델 API 헤더 매핑 호출은 0회다(3절).
3. **비식당 판별은 Gemini API로 했다.** 판정 경로 결정은 헤더 매핑만 다룬다. 이슈 본문은
   "`.env`를 로드해 classify를 돌린다"고 적었다.

## 3. 헤더 매핑 — 에이전트 판정 2,364표

미적중 표 2,363개와 캐시 검증 실패 1개를 판정해 `data/daegu/headermap-answers-v1.jsonl`에 남겼다.
모두 `claude-opus-5/claude-read-1`, revision 1이다. 판정 방법은 다음과 같다.

- 헤더 글자에서 역할 초안을 만들었다. 날짜·장소·금액 낱말 셋 이상, 또는 날짜+금액이나
  상호+금액이 있는 첫 행을 헤더로 봤다.
- 초안을 헤더→역할 조합 223종으로 묶어 모두 읽었다. 이상 표기(`집행급액`, 카드 승인 내역 서식,
  병합 헤더 옆 칸의 날짜)를 따로 확인했다.
- 실패한 표는 원본 격자를 열어 규칙을 고치거나 개별 판정했다.
- 모든 판정은 `extract`의 코드 검증을 그대로 거쳤다.

직접 읽고 정한 것은 다음과 같다.

| 표 | 판정 |
| --- | --- |

### 수성구 `(2026.N)` 제목 8건 (완료 기준 4)

읽는 규칙을 더했다. 이제 `(2026.1)`~`(2026.6)` 6건은 대상이고, `(2026.7)`·`(2026.8)` 2건은
`declared_out_of_range`다. 대상 6건 중 4월분(`FILE_00000141523QTOY`)은 원본 `총 계` 429,300이 지출
합과 달라 미해결이다. 나머지 5건은 매핑됐다.

이 규칙 변경으로 커밋된 다른 도시의 수집 장부에서 판정이 달라지는 원본은 셋이다
(옛 `period.py`와 전수 비교). 해당 산출물은 다시 내지 않았다.
- 서울 동작 62·서울 중구 1·인천 검단 1: 원래 대상 밖이다. 사유만 `posted_out_of_range`에서
  `declared_out_of_range`로 바뀐다.
- 부산 중구 `…사용내역(2026.7)` 1개: 대상에서 빠진다. 이 원본의 레코드는 0건이라 부산
  `records.csv`는 바뀌지 않는다. 다음 재실행에서 부산 `excluded_sources`가 1 늘어난다.

4. 임시 출력 build가 바꾼 `data/daegu/build.json`은 되돌렸다.

## 10. 명령

Git Bash, 저장소 루트에서 실행했다. 보조 스크립트는 다음과 같다.
- `run.py`: `.env`를 읽고(첫 인자가 `1`이면 GEMINI 포함, `0`이면 제외) 나머지 인자로 `cli.main`을
  부르는 실행기다.
- 도시 `fetch.json`: 일곱 기관의 `fetch.json`을 레지스트리 순서로 이어 붙여 만들었다(원본 2,074 ·
  누락 20 · 받지 않은 게시글 21,011 · 걸러 낸 게시글 505, #173 기록과 같다).
  `unattached_postings`(#212)는 기관 장부에 없던 칸이라 싣지 않았다.

```text
uv run python -m deliciousmap headermap --city daegu          # 모델 없음, 답변 이력 검증
uv run python -m deliciousmap parse --city daegu
run.py 1 classify --city daegu                                # 24분, 이어 실패 배치 재시도 2회
run.py 0 geocode --city daegu                                 # 1시간 52분, lookup-failed
run.py 0 geocode --city daegu --retry-failed                  # 대괄호 7건 남음 → 어댑터 수정 뒤 재실행
run.py 0 closure --city daegu
run.py 0 build --city daegu
# 기관마다(시청·동구·서구·남구·수성구·달성군·군위군)
uv run python -m deliciousmap headermap|parse --city daegu --org <slug>
run.py 1 classify --city daegu --org <slug>
run.py 0 geocode|closure|build --city daegu --org <slug>      # 동구·서구는 geocode --retry-failed
uv run python -m deliciousmap.ci check-data --data-root data
```
