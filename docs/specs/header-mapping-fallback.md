# 헤더 매핑 검증과 전량 추출 폴백

[#18](https://github.com/snowjaewon/OfficialDeliciousMap/issues/18)의 정책 문서다. 프로젝트 전체 LLM API 비용 한도 **15달러(USD)**는 2026-09-10 사용자 결정으로 확정했다. 나머지 처리 기준은 검토 제안이며, 파이프라인 구현·실측 결과가 아니다. 아키텍처 선택의 이유는 [ADR-0002](../adr/0002-ai-header-mapping.md)에 둔다.

## 코드 검증

- 검증 단위는 원본 안의 표 또는 카드 묶음이다. 원본 전체의 모든 대상 묶음이 통과해야 그 원본을 통과로 센다.
- 분모는 추출 성공 레코드 수가 아니라 원본에서 식별한 지출 후보 전체다. 빈 행·반복 헤더·합계·제목은 근거와 위치를 남기고 분모에서 뺀다. 날짜나 금액을 못 읽었다는 이유로 후보에서 빼지 않는다. 여러 행에 걸친 지출은 하나의 후보로 묶고 원본 위치를 연결한다. 후보 범위나 묶음 자체를 식별하지 못하면 검증 실패다.
- 후보 **100%**에서 집행일이 실제 날짜로 파싱되고, 금액이 단위 적용 후 유한한 숫자로 해석되며, 상호가 공백이 아니어야 한다. 기관·부서는 출처 메타데이터로 보완할 수 있지만 집행일·상호·금액을 추측해서 채우지 않는다. 연도 보완에는 확인 가능한 문서·게시글 근거를 남긴다.
- 2026년 상반기 밖의 유효한 지출은 범위 밖 건수와 사유를 기록하고 대상 레코드에 넣지 않는다. 기간 밖이라는 이유로 날짜 파싱 실패와 혼동하지 않는다. 원본에 실제로 존재하는 0원·음수는 즉시 추출 오류로 단정하지 않고 재검증 리포트의 검토 대상으로 남긴다.
- 후보가 0개면 비율을 계산해 자동 통과시키지 않는다. 실제 집행 없음이 확인되면 근거를 남기고 0건으로 통과시키며, 설명되지 않은 0건은 실패다. `layout=none`도 집행 없음의 증거로 보지 않는다.
- 헤더 없는 표는 비어 있지 않은 상위 12행의 값으로 매핑하고 공통 헤더 서명 캐시는 사용하지 않는다. 여러 표가 있으면 독립된 표마다 이 입력을 구성하고, 해당 표에 적용되는 제목·연도·단위의 출처도 전달한다. 같은 100% 기준을 적용하며, 헤더 부재만으로 전량 추출에 넘기지 않는다. 카드형은 별도 코드 파서 결과에 같은 검증 기준을 적용한다.

## 재호출과 폴백 진입

1. 원본을 격자 또는 카드로 읽고 헤더 매핑·코드 추출·검증을 실행한다. 합계가 있으며 대상 범위·단위를 확정할 수 있으면 코드 추출에서도 금액 합계를 정확히 대조한다. 불일치는 검증 실패다.
2. 실패 시 기존 캐시를 해당 원본에서 재사용하지 않고, 실패한 표의 비어 있지 않은 상위 12행과 문서 맥락·실패 사유로 헤더 매핑을 **표마다 1회 재호출**한다. 새 매핑으로 전체 후보를 다시 추출·검증한다. 캐시 미적중으로 최초 LLM 호출을 했더라도 추가 재호출은 표마다 1회뿐이다.
3. 여전히 검증에 실패하고 LLM이 읽을 수 있는 원본 내용과 대조 가능한 원본 위치가 있으면, 예산 안에서 원본 전체를 **1회 전량 추출**한다. 상위 12행만 전량 추출 입력으로 보내지 않는다. 원본 전체의 성공 결과 하나를 채택하며 코드 추출 결과와 합쳐 중복을 만들지 않는다.
4. 지원하지 않는 형식·DRM·내용 변환 실패는 자동으로 LLM에 넘기지 않는다. HWP/HWPX 파서 선택은 별도 티켓의 범위다. 입력을 읽을 수 없거나 응답이 잘렸거나 검증이 실패하면 자동 재호출을 반복하지 않고 파일 단위 미해결로 남긴다.

호출 장애는 잘못된 헤더 매핑의 증거가 아니다. API 오류·타임아웃은 사유를 남기고 해당 원본을 미완료로 처리한다. 자동 네트워크 재시도로 위 횟수 제한을 우회하지 않는다.

## 프로젝트 LLM API 비용 한도

**확정한 예산과 범위**

- 이번 프로젝트 전체의 LLM API 비용 한도는 **15달러(USD)**다. **헤더 매핑·비식당 판별·전량 추출 폴백**이 하나의 예산을 공유한다. 이전 제안의 폴백 전용 1,000,000토큰 상한은 폐기한다. 토큰은 사용량과 비용 계산을 위해 기록한다.
- 헤더 매핑은 원본의 열 역할·금액 단위를 판정하고, 비식당 판별은 고유 상호가 식당인지 판정한다. 지오코딩은 네이버 지역검색 API와 인허가 자료로 처리하며 LLM을 사용하지 않는다. 따라서 지오코딩 비용은 이 LLM 예산에 포함하지 않는다.
- 한도는 호출마다, 도시마다, 실행마다 새로 주어지는 금액이 아니다. 두 개발자의 프로젝트 호출, 프로토타입·재호출·실패 호출 중 과금된 사용량을 모두 합산한다. 기존 사용액은 제공자의 사용량/청구 기록으로 먼저 확인해 차감하며, 현재 잔액이 15달러라고 가정하지 않는다. 개발 도구 구독료는 LLM 파이프라인 API 예산과 별개다.

**한도 집행 방법과 폴백 파일 수는 검토 제안**

- 모든 LLM 요청 전에 해당 모델의 적용 단가와 입력·최대 출력·사고 등 과금 항목으로 요청 비용 상한을 예약한다. 과금 항목은 제공자 정의를 따라 중복 계산하지 않는다. 누적 사용액과 진행 중 예약액에 새 요청을 더해 15달러를 넘으면 요청하지 않는다. 단가나 요청 비용 상한을 확인할 수 없으면 자동 호출을 보류한다.
- 응답 뒤 실제 사용량으로 정산하고, 사용량을 확인할 수 없는 호출은 예약액을 유지한다. 실행 재시작에도 누적액을 보존한다. 두 개발자의 모든 LLM 호출에 공통 비용 기록과 예약을 적용하고, 공유 예약을 보장할 수 없으면 실행을 직렬화한다.
- 폴백은 별도로 7개 도시·2026년 상반기 수집 전체에서 **원본 100개** 상한을 제안한다. 이는 비용 한도가 아닌 예외 규모를 검토하기 위한 문턱이다. 원본 해시와 호출 이력으로 자동 중복 호출을 막고, 실패한 호출도 원본 수에 포함한다.
- 단일 원본이 남은 비용 한도나 모델 문맥 한도에 맞지 않으면 자르거나 일부만 성공 처리하지 않는다. 예산 부족은 해당 LLM 단계의 미완료 사유로 남긴다. 폴백 원본은 파일 단위 미해결로 보고하며, 예산 소진을 제출 통과의 예외로 삼지 않는다. 비용 한도는 사용자 결정 없이 자동 증액하지 않는다.

## 폴백 결과 검증

- 일반 추출과 동일한 후보 100% 검증에 더해, **폴백 원본마다 모든 지출의 집행일·상호·금액을 사람이 원본과 전수 대조**한다. 생성된 레코드만 보지 않고 원본에서 빠진 지출·허위 추가·중복도 확인한다. 근거 없는 상호 복원이나 값 추정은 허용하지 않는다.
- 원본에 합계가 있으면 해당 합계가 포괄하는 범위와 단위를 먼저 확인한 뒤 같은 범위의 추출 금액 합계와 정확히 비교한다. 합계와 소계를 이중으로 더하지 않는다. 합계가 없거나 범위가 불명확하면 대조 불가 사유를 남기고 전수 대조로 확인한다. 합계 일치만으로 날짜·상호·누락 검토를 대신하지 않는다.
- 코드 검사와 사람 대조가 끝나기 전에는 폴백 출력을 검토용으로 분리하고 장부에 적재하지 않는다. 오류가 있으면 해당 원본 전체를 미해결로 남기고 원인 수정 후 다시 검증한다.
- 원본 해시·출처·표/행 위치, 모델·프롬프트·스키마 버전, 호출 경로·사용량, 후보/추출/미해결 건수, 합계 대조와 검토자·결과를 정제 산출물로 추적한다. 원본 내용과 비밀키는 커밋하지 않는다.

## 끝내 읽지 못한 원본

- 기관 단위 **수집 보류**에 파싱 실패라는 새 사유를 더하지 않는다. 이미 받은 원본의 검증 실패·예산 초과·검토 미완료는 원본 해시별 파일 단위 손실/미해결로 집계한다. DRM 등 기존 수집 보류 사유에 해당하는 경우에는 기존 기관 상태도 함께 유지한다.
- 실패한 원본의 잘 읽힌 일부만 최종 레코드로 확정하지 않는다. 원본별 후보 수와 미해결 수를 알면 기록하고, 후보 수 자체를 모르면 `알 수 없음`으로 표시한다. 이를 0건 손실로 보고하지 않는다. 검증을 마친 다른 원본의 레코드는 보존한다.
- 중간 빌드와 다음 도시 진행은 허용하되, 자료 범위와 미해결 원본을 재검증 리포트에 표시한다. 제출 전에는 미해결 원본이 **0개**여야 한다. 사유 기재·예산 소진·원본 제거만으로 통과시키지 않는다. 이는 [#9의 제출 기준](https://github.com/snowjaewon/OfficialDeliciousMap/issues/9#issuecomment-5611347945)을 구체화한다.

## 후속 구현의 검증 사례

후속 구현에서 테스트할 공개 인터페이스는 별도로 합의한다. 행동 사례는 정상 표, 천원 단위, 월/일 분리, 헤더 없는 표, 카드형, 실제 집행 없음, 후보 한 건의 필수값 누락, 합계 불일치, 캐시 오매핑 후 복구, 폴백 전수 대조 실패, 예산 경계와 재실행 시 누적량 유지다. 이 문서 변경에는 실행 코드·테스트 인터페이스를 도입하지 않는다.
