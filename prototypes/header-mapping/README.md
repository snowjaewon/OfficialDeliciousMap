# 프로토타입: LLM 헤더 매핑 정확도 (2026-09-09)

이슈 [#10](https://github.com/snowjaewon/OfficialDeliciousMap/issues/10) (parent #1) 산출물. **버리는 코드**다.
질문: *Gemini에 원본의 상위 몇 행만 주면 열 역할(집행일·부서·상호·목적·금액)과 금액 단위를 얼마나 정확히 판정하는가.*

## 방법

1. `fetch.py`·`fetch2.py` — 7개 도시 35개 게시판에서 2026 상반기 위주로 원본 98개를 내려받았다(중복 제거 후 88개). 원본은 저장소 밖(`raw/`, 미커밋).
2. `extract.py` — 형식을 매직 바이트로 판정하고(xlsx·xls·pdf·html; hwp·hwpx 5개는 미지원으로 제외) 첫 시트/첫 표의 **비어 있지 않은 상위 12행 × 16열**을 격자로 뽑았다 → `grids.json` (83개).
3. `gold.json` — 83개를 사람이 라벨링(헤더 행 번호, 역할별 헤더 글자, 단위, 레이아웃).
4. `llm.py` — `gemini-3.6-flash`, `thinking_level=minimal`, `temperature=0`, `response_json_schema`. 프롬프트·스키마는 아래. 결과 `results.json`.

채점: 역할은 모델이 고른 열의 헤더 글자와 정답 헤더 글자를 공백 무시로 비교. 헤더 행이 없는 표(용산 PDF 1건)는 열 번호로 비교.

## 비용과 캐시

- 호출당 약 **$0.0042**(3.6 Flash $1.50/$7.50 per 1M, #6 기준). 캐시 없이 20,000파일이면 약 $85.
- 헤더 서명(헤더 행 글자를 공백 제거해 이어붙인 것) 기준으로 표본 83개는 **64개 서명**. 게시판 하나에 2~3개씩만 받은 표본이라 적중률 23%지만, 반복 구조는 뚜렷하다: 시청·구청장 게시판은 매달 같은 양식(대구시청 3/3, 대전 중구 3/3, 유성 3/3, 서울시청 2/2), 부서별 게시판은 부서마다 양식이 다르되 같은 부서는 매달 같다(용산 3파일 3양식).
- 추정: 전체 서명 수는 "부서 수"에 수렴 → 1,500~3,000개 → **$6~13**. 캐시 키는 `(헤더 행 정규화 글자, 열 수)`. 헤더 없는 표는 캐시 불가(매번 호출, 표본 83 중 1건).
- 캐시 적중이라도 **데이터 값 검증은 코드가** 한다(날짜 파싱 가능 여부, 금액 숫자 여부). 검증 실패 → 서명 무시하고 재호출.

## 발견한 것 (설계에 반영할 것)

1. **격자에 데이터 행을 함께 줘야 한다.** 헤더가 사라진 PDF(용산 부동산정보과)도 값 모양으로 역할을 맞혔고, 단위 표기가 없는 파일의 단위도 값 크기로 판정한다. "헤더+상위 3행"이 아니라 **비어 있지 않은 상위 12행**을 주는 것이 맞다(제목·요약 행이 3~4행 차지).
2. 스키마에 `layout`·`header_rows`·`data_start_row`가 있어야 한다. 요약 행(`계`) 건너뛰기와 2단 헤더가 이걸로 풀린다.
3. `month`/`day`/`time` 역할이 필요하다(미추홀구 월|일, 다수의 일자|시간 분리). 연도는 `year_hint`(제목에서) — 유성구 PDF는 날짜 열에 연도가 없다.
4. **형식별 함정은 헤더 매핑 밖의 일이다**: PDF 숫자 분리(`3 80,000`), 엑셀 날짜 시리얼(46246)·시각 소수(0.689), 동구(울산) HTML의 셀 안 라벨 반복, 강남 xls의 `1.0` 연번. 행 추출 코드가 처리.
5. **key_value 레이아웃**(관악·서대문 카드형)은 헤더 매핑이 아니라 별도 파서 대상. 서대문 `집행액(천원)`은 여기서도 단위 판정이 맞았다.
6. 미지원 형식: HWP(부산 사상구 3건), HWPX(부산 동래구·광주 남구 2건). 헤더 매핑 이전 단계(파서) 결정이 필요.
7. 전량 추출 폴백은 이 표본에서 필요한 경우가 **0건**. 폴백 조건은 "헤더 매핑 결과를 코드가 검증했을 때 실패"로 좁혀도 된다.

## 프롬프트·스키마 초안

`llm.py`의 `SYSTEM`과 `SCHEMA` 그대로. 요지:

- 입력: `파일 형식 / 게시글 제목 / 시트명 / 격자(r0: [0]셀 | [1]셀 …)`.
- 출력: `layout`, `header_rows[]`, `data_start_row|null`, `columns[{col, role, header_text}]`, `amount_unit(won|thousand_won|unknown)`, `year_hint|null`, `note`.
- 역할 enum: date, month, day, time, dept, user, place, purpose, amount, count, method, category, address, seq, other.
- 지시 핵심: 제목·단위·요약 행은 헤더가 아님 / 사람 직함은 user, 부서명은 dept / `사용장소`가 동네이고 `가맹점명`이 따로 있으면 가맹점명이 place / 단위는 헤더·상단 행·값 크기 순으로 판단 / 헤더가 없어도 값으로 추정.

## 재현

```bash
# .env 의 GEMINI_API_KEY, GEMINI_MODEL 사용
python fetch.py && python fetch2.py   # raw/ 에 원본 (저장소 밖)
python extract.py                     # grids.json
python llm.py                         # results.json + 요약. llm_cache.json 으로 재호출 방지
```
