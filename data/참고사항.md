# 참고사항 — 아직 산출물에 넣지 않은 판정

이 파일은 정제 산출물이 아니다. **다음 실행 때 사람이 먼저 넣어야 하는 판정**을 모아 둔 쪽지다.
넣고 나면 그 항목을 지운다.

## 1. 남구 `1112-1.hwpx`의 헤더 판정 (#112)

### 무엇인가

이 원본의 표에서 **어느 열이 집행일이고 어느 열이 금액인지** 정한 판정이다. 같은 남구
`.hwpx` 4개 중 나머지 셋은 헤더 서명이 `data/_shared/headermap.jsonl`에 이미 있어 그대로
읽힌다. `1112-1`만 헤더가 `대상 인원수(명)`·`금액(원)`으로 단위를 달고 있어 서명이 다르고,
이 판정이 없으면 `headermap`이 `model_not_configured`로 남긴다.

### 왜 아직 안 넣었나

[#112](https://github.com/snowjaewon/OfficialDeliciousMap/issues/112)가 형식 지원까지를
범위로 잡고 `data/` 반영을 후속으로 미뤘다. 판정 자체는 #99와 같은 방식으로 Claude가 표를
직접 읽어 정했고 코드 검증(`extract`)을 통과하는 것까지 확인했다. 실측은
[docs/validation/issue-112.md](../docs/validation/issue-112.md)에 있다.

### 넣으면 무엇이 달라지나

| | 지금 (이 판정 없이) | 넣은 뒤 |
| --- | --- | --- |
| 남구 레코드 | 1,022 + 5 | 1,022 + **14** |
| `1112-1` | `model_not_configured` 미해결 | 9건 통과 (`total_check=matched`) |

`unsupported_format`은 이 판정과 무관하게 이미 0개다. 이 판정이 푸는 것은 형식이 아니라
헤더 열 역할이다.

### 어떻게 넣나

아래 한 줄을 두 파일에 넣는다. **두 파일 모두 키 정렬 JSONL이라 끝에 붙이면
`cache must have unique, sorted key/revision pairs`로 거부된다.** `key` 값 기준으로 제자리에
끼워 넣어야 한다.

- `data/gwangju/orgs/gwangju-nam/headermap-answers-v1.jsonl`
- `data/gwangju/headermap-answers-v1.jsonl`

```json
{"evidence": "claude-opus-5/claude-read-1 c8242c0c9040d26b table1", "key": "6585a8eb5f348f15ef706c135c8fddfbff1d412dc443fcca05312c7908770812", "revision": 1, "schema_version": 1, "valid": true, "value": {"answer": {"amount_unit": "won", "columns": [{"column": 1, "role": "spent_on"}, {"column": 2, "role": "merchant"}, {"column": 3, "role": "purpose"}, {"column": 5, "role": "amount_krw"}], "data_start_row": 3, "header_rows": [1], "layout": "table", "year_hint": null}, "error": null, "model": "claude-opus-5", "prompt_version": "claude-read-1"}}
```

넣은 뒤 `headermap`을 돌리면 코드가 검증하고 공통 캐시
`data/_shared/headermap.jsonl`에 서명 하나를 스스로 쌓는다(426줄 → 427줄). 다음 분기의 같은
헤더는 이 캐시로 판정 없이 읽힌다.

### 판정의 근거

```text
R1  사용자 | 일시 | 장소 | 집행목적 | 대상 인원수(명) | 금액(원) | 결제방법 | 비목
R2  합 계[colSpan=5] | | | | | 639,100 | |
R3  회계과장 | 2026.01.02.12:30 | ... | 50,400 | ...
```

- `header_rows: [1]` — 1행이 헤더다.
- `data_start_row: 3` — 2행은 합계 행이라 첫 지출은 3행이다.
- 열 역할은 0부터 센 번호로 집행일 1, 상호 2, 목적 3, 금액 5다.
- `year_hint: null` — 일시에 연도가 있어 짐작할 것이 없다.
- `amount_unit: "won"` — 원 단위다.

합계 639,100원이 9건의 합과 정확히 같아 `total_check`가 `matched`로 통과한다.

### 넣은 뒤 남는 일

레코드 14건을 지도에 올리려면 남구를 `parse`부터 `build`까지 다시 돌려야 하고, 그때
`classify`·`geocode`가 새 상호를 판정한다. `1112-1`의 9건 중 3건은 상호 칸에 쉼표로 두
업소가 적혀 있어 좌표를 받지 못한다([#117](https://github.com/snowjaewon/OfficialDeliciousMap/issues/117)).
